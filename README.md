# dsa

NeetCode 150, in Python. Sep 2026 - Dec 2026.
One sheet. Picked and locked. No other sheet gets opened.

## Layout

    arrays/0217_contains_duplicate.py     one file per problem
    two_pointers/
    notes/                                the pages that actually get reread
    log.md                                one row per attempt
    _template.py                          copy this to start a problem

Filename is `<section>/<4-digit LC number>_<snake_case_title>.py`.
Zero-padding matters - it keeps the directory sorted by problem number.

## The rules

**Every attempt gets a log row.** Solved, failed, read the editorial - all of it.
The log is the only revision asset that isn't already on the internet.

**The 25-minute rule.** Stuck 25 minutes with *no approach at all*? Read the
editorial. Then close it and re-solve from an empty file the next day, unaided,
and mark the original attempt `unaided = N`.
It is not "25 minutes then give up" - if you have an approach and you're
debugging it, keep going, that's the valuable part. It fires only when you
genuinely cannot see a way in.

**Say the brute force out loud first.** Before writing a line of code: the brute
force and its complexity, then the complexity you're aiming for. Every
interviewer asks. Most candidates fumble it.

**Log and stop.** Finishing at 01:30 costs you tomorrow's session.
